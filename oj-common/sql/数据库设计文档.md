# OJ 系统数据库设计文档

## 1. 概述

本文档描述了 OJ（Online Judge）在线判题系统的数据库设计。数据库名称为 `oj-system`，采用 UTF-8MB4 字符集，支持完整的 Unicode 字符。

## 2. 数据库架构

### 2.1 核心业务模块

数据库设计分为三个主要业务模块：

1. **帖子社区模块** - 用户交流讨论功能
2. **题目判题模块** - 核心的在线判题功能
3. **系统管理模块** - 用户、角色、权限、文件管理

## 4. 设计特点

### 4.1 逻辑删除

所有业务表都采用逻辑删除设计（del_flag 字段），不直接物理删除数据，便于数据恢复和审计。

### 4.2 审计字段

大部分表都包含以下审计字段：
- `creator` / `create_time` - 记录创建人和创建时间
- `updater` / `update_time` - 记录更新人和更新时间

### 4.3 JSON 存储

部分字段使用 JSON 格式存储复杂数据：
- `tags` - 标签数组
- `judge_case` - 判题用例数组
- `judge_config` - 判题配置对象
- `judge_info` - 判题结果信息

### 4.4 索引优化

针对高频查询字段建立索引：
- 用户ID索引 - 快速查询用户相关数据
- 帖子/题目ID索引 - 快速关联查询
- 唯一索引 - 保证数据唯一性（如用户名）

### 4.5 字符集

全库使用 `utf8mb4` 字符集，支持完整的 Unicode 字符，包括 Emoji 表情。

## 5. 关系图

```
sys_user (用户)
    ├─ 1:N → oj_post (发布帖子)
    ├─ 1:N → oj_post_comment (发表评论)
    ├─ 1:N → oj_post_favour (收藏帖子)
    ├─ 1:N → oj_post_thumb (点赞帖子)
    ├─ 1:N → oj_problem (创建题目)
    ├─ 1:N → oj_problem_submit (提交代码)
    ├─ N:M → sys_role (通过 sys_role_user)
    └─ 1:N → sys_file (上传文件)

oj_post (帖子)
    ├─ 1:N → oj_post_comment (评论)
    ├─ 1:N → oj_post_favour (收藏)
    └─ 1:N → oj_post_thumb (点赞)

oj_problem (题目)
    ├─ 1:N → oj_problem_comment (评论)
    └─ 1:N → oj_problem_submit (提交记录)

sys_role (角色)
    ├─ N:M → sys_user (通过 sys_role_user)
    └─ 1:N → sys_role_permission (权限)
```

## 7. 总结

该数据库设计涵盖了一个完整的在线判题系统所需的核心功能：

1. **用户系统** - 完善的用户管理、角色权限体系
2. **题目管理** - 支持题目创建、提交、判题的完整流程
3. **社区功能** - 帖子发布、评论、点赞、收藏等社交功能
4. **文件管理** - 统一的文件上传和管理

设计遵循了良好的数据库设计原则，包括逻辑删除、审计追踪、索引优化等，为系统的稳定运行和后续扩展提供了良好的基础。
